Todo - A lightweight project todo list

**Usage:**

  todo add TEXT...
  todo list FILTER...
  todo edit ID [TEXT...]
  todo del FILTER...
  todo help

**Aliases:**

  add  => a, new
  list => l, ls
  edit => e
  del  => d, rm
  help => h

**Arguments:**

  TEXT    description text with optional tag or connection operations
  FILTER  words, IDs, ID ranges, tags, or connections used to select tasks
  ID      task ID or range; join multiple selections with `/`
  TAG     starts with a letter or digit; may contain hyphens or underscores

  Spaces between filters mean AND. `/` means OR within one filter group.
  An OR group may combine different filter types.

**Operators:**

  Everything is ordinary text except the operator forms below.

  +  Add or Has
     todo edit 12 +defer
     todo list +high

  -  Remove or Doesn't Have
     todo edit 12 -defer
     todo list -blocked

  /  OR when selecting tasks
     todo list +maybe/+consider
     todo rm 3/4/5
     todo rm 3/4/5/+low

  .. Inclusive task ID range; either end may be omitted
     todo list 1..10
     todo list ..10
     todo list 20..
     todo edit 2..4/8 +ready

  :  Treat a leading + or - as text
     todo add Test the :-h flag and :+draft syntax
     todo list :-h

  After `+` or `-`, an all-digit value is a connection. Other valid values are
  tags.

  A prefix is special only when the whole token is valid. `+tag` adds a tag;
  the separate words `+ tag` are ordinary text. Invalid operations and
  standalone `+`, `-`, or `--` are also ordinary text.

  The `:` literal marker is removed before storing or matching.
  Removals during `todo add` are accepted and have no effect.

**Editing:**

  During `todo edit`, ordinary text replaces the description.
  Edits with only tag and connection operations preserve the description.

  With no text, `todo edit ID` opens the complete task in an inline editor.
  Enter saves the edit. Ctrl+C cancels it. Interactive edits require a terminal.
  In scripts, provide the edit text on the command line.

  Multiple IDs and ranges receive the same tag and connection operations
  atomically. Bulk selectors (any range or selections joined with `/`) cannot
  replace task descriptions or open the interactive editor, even if only one
  task matches.

**Ranges:**

  Ranges select existing IDs, not a count of tasks. Missing IDs in a range are
  skipped. Explicitly named IDs must exist for edits and deletions.

  Edits and deletions fail when a range selection matches no tasks.
  Listing an empty range returns no output.

  Reversed ranges and bare `..` are invalid. Ranges select tasks, not
  connections.

**Deleting:**

  `todo del` accepts the same filters as `todo list`. Use `todo list` to
  preview. Deletion removes every match atomically and prints each removed task.
  Keep this output if you need to recover the task details.

**Connections:**

  Connections are symmetric. Adding `+2` to task 1 also shows `+1` on task 2.
  Removing a connection from either task removes it from both.

**Examples:**

  Add and prioritize work:
    todo add Prepare for deployment +production +now

  Find actionable production tasks:
    todo list +production +now -blocked

  Complete a task without replacing its description:
    todo edit 1 -now +done

  Connect related tasks, then list either one:
    todo edit 1 +2
    todo list 1/2

  List task 2 OR tasks connected to task 2:
    todo list 2/+2

  Apply the same edit to several tasks atomically:
    todo edit 2/3 +ready -defer

  Tag a batch of recently added tasks:
    todo edit 20.. +maybe -consider

  View the beginning or end of the list by ID:
    todo list ..10
    todo list 20..

  Preview an ID range before deleting it:
    todo list 1..10
    todo del 1..10

  Preview completed tasks before deleting them:
    todo list +done
    todo del +done

**Storage:**

  The default database is `.todo.sqlite` in the nearest Git root, or the current
  directory outside Git. Set TODO_FILE to use an exact database path.

**Backups:**

  Backups are disabled by default. Enable them in a dedicated `.todo` directory:

    export TODO_BACKUP=on         # keep 10 snapshots in .todo
    export TODO_BACKUP=.todo      # choose a directory; default count is 10
    export TODO_BACKUP=30@.todo   # choose both count and directory

  Relative paths resolve beside the database. Successful changes save the
  previous database as PROJECT-TIMESTAMP.sqlite. Only the newest snapshots are
  retained.

  Errors and edits that change nothing do not add backups.
  Backup creation failures stop the change.

  Todo claims only absent or empty directories, creating `.backupid` with the
  database's canonical path. Existing directories require a matching
  `.backupid`. Use one backup directory per database and exclude it from version
  control.

  To restore, stop any running Todo commands and copy the chosen snapshot over
  the database. This restores everything, including the task ID counter.

**Output:**

  Tasks use the stable format `ID DESCRIPTION +TAG +REFERENCE`. Terminal output
  adds color and wrapping; redirected output remains plain, one task per line.
  Set NO_COLOR to a non-empty value to disable terminal colors.
